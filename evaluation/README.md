# SemanticGuard AI — Evaluation

## Dataset

`datasets/synthetic_pairs.csv` is a deterministic, controlled synthetic passage-pair dataset generated by `datasets/generate_synthetic_pairs.py`. It contains 10 queries, 10 candidate passages, and the complete 100-pair query/candidate matrix. Each of the five scenarios has two queries:

- `exact_copy`: the positive candidate is text-identical to the source passage.
- `paraphrasing`: the positive candidate restates the same specific claim with different wording.
- `partial_copy`: the positive candidate repeats a substantive sentence while adding different surrounding content.
- `common_topic_independent`: same-topic passages express distinct facts and are labeled non-matches.
- `unrelated`: unrelated passages are labeled non-matches.

Labels are controlled by construction, not human judgments on real submissions. Regenerate the CSV with:

```bash
python evaluation/datasets/generate_synthetic_pairs.py
```

## Run the benchmark

From the repository root:

```bash
cd backend
.venv/bin/python ../evaluation/benchmark.py --candidate-k 5 --top-k 1 --repeats 3
```

The benchmark compares FAISS-only ranking and Cross-Encoder ranking over **identical FAISS candidate sets**. `candidate-k` controls retrieval depth; `top-k` controls the final scored list. The report separately shows FAISS candidate recall, conditional reranker recall among retrieved positives, Precision@K, Recall@K, F1@K, MRR, nDCG@K, and confusion counts overall and by scenario.

Outputs are written to `evaluation/results/`:

- `pairwise_results.csv`: labels, cosine scores, FAISS ranks/candidate membership, Cross-Encoder scores/ranks, and final top-K flags.
- `aggregate_metrics.csv`: overall and per-scenario metrics, confusion counts, model loading times, and inference times.
- `benchmark_report.md`: run metadata, dataset SHA-256, result tables, timing, observed deltas, and limitations.

Model loading is timed separately from inference. The first timing pass warms up each model; inference durations are means over the requested repeats. FAISS timing on macOS includes the worker process startup. Model loading includes any network download if weights are not cached. All inference and evaluation run locally; no external API is used.


## Limitations

This small synthetic corpus is a reproducible software/evaluation smoke test, not a representative plagiarism benchmark. Its labels reflect deliberately authored examples and do not cover real student writing, assignment prompts, citations, discipline-specific language, multilingual text, or adversarial paraphrasing. Similarity and reranker scores are ranking signals, not plagiarism probabilities or misconduct decisions. No general plagiarism-detection accuracy claim should be inferred from these results.

## Phase 4 hybrid false-positive evaluation

`datasets/hybrid_validation.csv` and `datasets/hybrid_test.csv` are controlled synthetic pair sets with disjoint topic and template identifiers. The benchmark rejects overlap. Regenerate both datasets with:

```bash
python evaluation/datasets/generate_phase4_data.py
```

Run from the repository root:

```bash
backend/.venv/bin/python evaluation/phase4_benchmark.py
```

Weights and the hybrid review threshold are selected using validation F1, with specificity as the first tie-break, then persisted in `results/hybrid_calibration.json`. Test labels are used only after this config is frozen. Outputs include `hybrid_test_pairs.csv`, `phase4_metrics.json`, and `phase4_report.md`, with per-scenario confusion counts/FPR, separate model loading and inference times, and a process peak-memory delta. Each test row contains one labeled candidate, so this pairwise benchmark measures threshold decisions, not retrieval recall or ranking quality; use the Phase 3 full-candidate benchmark for retrieval/ranking.

This small synthetic split is a deterministic code and calibration-leakage check, not evidence of general coursework detection performance. Its validation-selected configuration is not calibrated for real assignments.
